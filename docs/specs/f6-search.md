## 1. 背景与动机

按关键词跨内容检索:找文献、找经验帖、找笔记。MVP 用数据库 LIKE(标题+正文),全文搜索升级见灵感库 F14。

## 2. 行为需求

- `GET /api/search?q=xxx&type=document`:
  - **q 必填**,非空(空 → 400 `VALIDATION`);
  - 匹配范围:文档**标题 + 正文**(LIKE,大小写不敏感);
  - **可见性**:公开文档 + 本人私有文档(他人私有不泄露);
  - 排序:标题命中优先,其次创建时间倒序;
  - 限制:最多返回 50 条;
  - `type` 参数:document / resource / task;默认(type 缺省)聚合三类;**F7/F9 上线后 resource/task 已并入**(2026-08-22);
  - 响应:`{documents: [], resources: [], tasks: []}`(三组结构固定,阶段 1 后两组为空)。

## 3. 接口

契约 §F6:`GET /api/search` query:`q, type?`。

## 4. 验收标准(可测清单)

- [ ] q 为空/缺失 → 400 `VALIDATION`
- [ ] 标题命中返回;正文命中返回
- [ ] 公开文档(他人发布)可被搜到
- [ ] 本人私有文档可被搜到;他人私有 → 不出现
- [ ] 标题命中的排在正文命中的前面
- [ ] 结果 ≤ 50 条
- [ ] type=resource / type=task → 对应数组为空;type 非法 → 400
- [ ] 未登录 → 401

## 5. 边界与异常

- LIKE 通配符:对用户输入转义 % / _(防通配符注入);
- 空 q 在 handler 层拦截(400),service 层同样防御;
- 阶段 1 后两组固定返回空数组(结构稳定,前端无需改动)。

## 6. 测试计划

- 单元(service):命中范围、可见性过滤、排序(标题优先)、上限;
- handler:q 校验、401、分组结构。
