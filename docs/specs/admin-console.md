## 1. 背景与动机

**契约上有 `/admin/*` 五个接口,但 Go 后端从未实现**:邀请码只能 SQL 手工插入、改角色无 API、
成员列表无接口(加项目成员手填 UUID 的根源之一)。本次把管理端落地为可用的第一个版本,
并顺带承接 F9 v2 落地的任务类型字典的**管理界面**(此前只有只读 `GET /task-types`)。

## 2. 角色与权限(沿用 PRD,不重构)

- 管理端 API 全部挂 `/api/admin/*`,**仅 `admin` 角色可调**;supervisor/student → 403。
- 前端管理入口(`/admin`)仅对 `admin` 显示;supervisor 与 student 看不到。
- 权限判断:admin 校验在 service 层(`can` 语义),handler 不散落硬编码。
- **导师只读总览(F16)不进入本次范围**,另开会话讨论。

## 3. 功能需求

### 3.1 成员管理(admin)

- **列表**:全部成员(不含 password_hash),按 display_name 排序;支持 `q` 关键词过滤
  (username / display_name 子串,可空 = 全量)。组 ≤10 人,不分页。
- **改角色**:角色三选 `admin | supervisor | student`;调角色即时生效(下次请求按新角色鉴权)。
- **防锁死约束**:
  - 不允许把**自己**改成非 admin;
  - 不允许把**最后一个 admin** 降级(系统必须保留 ≥1 个 admin)。
  - 违反 → 400 `VALIDATION`。
- 不做账号停用/删除(PRD 未要求,本次明确排除)。

### 3.2 邀请码管理(admin)

- **生成**:
  - 自动生成随机码(默认);
  - 也可由管理员**自定义码**(手动输入,唯一冲突 → 409 `CONFLICT`);
  - 本次不做有效期 UI(默认永久有效,`expires_at` 恒空);
  - 不做用途备注字段(不引入 schema 新列)。
- **列表**:全部邀请码,展示 code / 创建时间 / 创建人 / 使用状态(未用 | 已用,含使用人与时间)。
- **撤销**:删除指定邀请码(无论是否已用),204;已删除码不能再用于注册(注册校验码必须存在)。

### 3.3 任务类型管理(admin)

- **列表**:全部类型(含停用),admin 专用端点;公开只读 `GET /task-types` 仍只返回 active(不动)。
- **新建**:name 必填、color 默认 `#94a3b8`、sort 默认排最后;同名 → 409。
- **编辑**:改名 / 改颜色 / 调排序 / 停用-启用(active)。
- **删除**:内置与自建类型**同权,均可物理删除**;删除时引用该类型的任务 `type_id` 置空
  (回退未分类);删除在事务中执行(删类型 + 置空引用任务)。
- **停用语义**:
  - 停用后:新任务下拉不再出现(公开列表过滤);
  - 已引用该类型的任务**仍显示原类型名与颜色**(任务视图查全量字典,不随停用丢失)。
  - 为支持这一点,任务视图组装改用"全量类型表"(与公开下拉过滤 active 分开)。

## 4. 接口(契约 §管理端 落地)

| 方法 | 路径 | 权限 | 请求体 | 响应 |
|---|---|---|---|---|
| GET | `/api/admin/users` | 👑 | query:`q?` | `{users: []}` |
| PATCH | `/api/admin/users/:id/role` | 👑 | `{role}` | `{user}` |
| GET | `/api/admin/invites` | 👑 | — | `{invites: []}` |
| POST | `/api/admin/invites` | 👑 | `{code?}`(空=自动生成) | `201 {invite, url}` |
| DELETE | `/api/admin/invites/:id` | 👑 | — | `204` |
| GET | `/api/admin/task-types` | 👑 | — | `{task_types: []}`(含停用) |
| POST | `/api/admin/task-types` | 👑 | `{name, color?}` | `201 {task_type}` |
| PATCH | `/api/admin/task-types/:id` | 👑 | `{name?, color?, sort?, active?}` | `{task_type}` |
| DELETE | `/api/admin/task-types/:id` | 👑 | — | `204`(内置/自建均可删;任务 type_id 置空) |

- `invite` 结构:`{id, code, created_by, used_by?, used_at?, created_at}`;`url` = 注册页链接(前端生成)。
- 错误:403 非 admin;401 未登录;400 校验/防锁死;404 不存在;409 重名/码冲突。

## 6. 边界与异常

- 角色调整即时生效但**当前已签发 access token 的 role claim 不变**,至多 15 分钟过期后按新角色;
  行为可接受(不引入 token 主动吊销)。
- 撤销邀请码对"已用"码:用户已注册不受影响,仅防再次使用。
- 删除任务类型(含内置)在事务中执行:删类型 + 引用该类型的任务 `type_id` 置空。

## 7. 测试计划

## 8. 前端形态

- React `/admin` 单页,顶部三 tab:**成员 / 邀请码 / 任务类型**;
- 顶栏对 `admin` 显示「⚙ 管理」入口(复用 finance 的角色过滤模式);
- 操作均为 shadcn Dialog/Select 表单;错误经 sonner toast 提示。
